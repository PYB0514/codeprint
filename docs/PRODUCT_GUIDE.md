# Codeprint — 제품 총정리 가이드

> 이 문서 하나만 읽으면 Codeprint가 뭘 하는 서비스인지, 사용자가 뭘 경험하는지, 무엇을 잡아내는지 전부 파악할 수 있도록 만든 안내서다. 실제로 써보지 않아도 이해가 가는 걸 목표로 한다.
>
> 더 깊은 내용이 필요하면: 기능 요약(사용자 관점) → [`USER_FEATURES.md`](USER_FEATURES.md) · API 전체 목록 → [`FEATURES.md`](FEATURES.md) · DDD 아키텍처·데이터 모델 → [`ARCHITECTURE.md`](ARCHITECTURE.md) · 분석 엔진 내부 로직 → [`ANALYSIS_ENGINE.md`](ANALYSIS_ENGINE.md) · 기술 스택·개발 방식 → [`PROJECT.md`](PROJECT.md).
>
> 이 문서에서 다루지 않는 것: 사업 전략·수익 구조 세부·경쟁 분석·미공개 보안 결함 등은 내부 규약상 로컬 전용 문서(`PRODUCT_STRATEGY.md` 등, gitignore 처리됨)로만 관리한다.

## 1. 한 줄 소개

**Codeprint는 GitHub 레포지토리를 입력하면 파일 구조·함수 호출 흐름·DB 연결 관계를 인터랙티브 회로도로 시각화하고, 구조적으로 위험한 패턴을 자동으로 잡아내는 개발자용 서비스다.**

코드를 한 줄도 읽지 않고 "이 프로젝트가 어떻게 짜여 있는지"를 파악하는 데 걸리는 시간을 줄이고, 사람이 놓치기 쉬운 아키텍처 위반(계층 역전, 순환 의존, 도메인 경계 침범 등)을 머지 전에 기계적으로 잡아낸다.

## 2. 누가, 왜 쓰는가

- **새로운 코드베이스에 합류한 개발자** — 온보딩 시간을 줄이려고. 문서보다 그래프가 실제 구조를 더 정확히 보여준다.
- **레거시/스파게티 코드를 맡은 개발자** — 어디가 얽혀 있는지 눈으로 확인하고, 리팩토링 우선순위를 정하려고.
- **아키텍처를 지키고 싶은 팀** — PR마다 사람이 리뷰로 잡던 구조 위반(레이어 역전, 도메인 경계 침범 등)을 자동 게이트로 강제하려고.
- **면접·포트폴리오용으로 자기 프로젝트를 보여주고 싶은 사람** — 코드를 링크로 보내는 대신 그래프로 구조를 설명하려고.

## 3. 처음 써보면 벌어지는 일 (핵심 흐름)

1. GitHub 계정으로 로그인한다.
2. 분석하고 싶은 레포 URL을 입력한다(본인 레포가 아니어도 공개 레포면 가능).
3. 서버가 레포를 clone해 최대 500개 파일을 읽고, 언어별로 함수·import·DB 접근·API 엔드포인트·서비스 간 호출을 추출한다(평균 10~60초, 첫 방문은 서버 콜드스타트로 조금 더 걸릴 수 있음).
4. 결과가 노드(파일/함수/DB 테이블/API 엔드포인트)와 엣지(호출·참조 관계)로 이루어진 인터랙티브 그래프로 열린다.
5. 그래프 옆 패널에 구조 경고가 나열된다 — "이 함수가 인프라 코드를 직접 참조한다", "여기 순환 의존이 있다" 같은 것들이 파일·줄 단위로 짚어진다.
6. 필요하면 노드를 클릭해 흐름 재생(호출 경로를 API→함수→DB까지 단계별로 따라가기)을 보거나, 경고를 숨기거나, 그래프를 다른 사람에게 공유하거나, 커뮤니티에 게시한다.

## 4. 그래프 화면에서 보는 것

- **노드 4종**: 파일, 함수, DB 테이블, API 엔드포인트.
- **관계(엣지)**: import, 함수 호출, 인스턴스화, DB 읽기/쓰기/생성/수정/삭제, 프론트→백엔드 API 호출, 서비스 간 동기 호출.
- **뷰 전환**: 계층형(디렉터리 트리 기준) ↔ 도메인형(바운디드 컨텍스트/기능 단위로 묶기), 이름/주석 라벨 토글.
- **노드 예산**: 함수가 80개를 넘는 대형 그래프는 처음엔 "복잡도 허브"(호출이 몰린 핵심 함수)만 보여주고, 전체 보기는 선택 사항이다 — 큰 레포일수록 처음부터 다 펼치면 오히려 파악이 어렵기 때문.
- **흐름 재생**: 함수를 클릭하면 그 함수를 호출한 곳(상류)과 그 함수가 호출하는 곳(하류)을 API 엔드포인트나 DB 접근까지 단계별로 재생 — 분기가 여러 개면 선택해서 따라갈 수 있다.
- **국소분석**: 프로젝트 설정에서 특정 하위 경로만 분석하도록 좁힐 수 있다. 모노레포처럼 정말 보고 싶은 디렉터리가 500파일 상한 때문에 잘려나가는 경우에 쓴다.

## 5. 20종 구조 경고 — 무엇을, 왜 잡는가

경고는 세 축으로 나뉜다: **①의존 방향**(위쪽 계층이 아래쪽만 알아야 하는데 거꾸로 된 경우) **②경계 침범**(모듈/도메인/기능 폴더가 서로를 몰라야 하는데 직접 참조하는 경우) **③런타임에 실제로 깨지는 코드**(정적으로 보이지만 실행하면 버그가 되는 패턴). 아래 설명은 앱이 사용자에게 실제로 보여주는 문구를 그대로 옮긴 것이다(단일 소스: `frontend/src/i18n/locales/ko/workspace.json`).

| 경고 | 무엇을 잡는가 |
|---|---|
| 순환 의존(CYCLIC_IMPORT) | 파일들이 서로를 import해 고리를 이룬다 — 한쪽만 고쳐도 연쇄로 영향받고 초기화 오류의 원인이 된다. |
| 핵심 로직 → 인프라 의존(DOMAIN_IMPORTS_INFRA) | 비즈니스 로직이 DB·외부 연동 코드를 직접 import한다 — 핵심 로직이 특정 기술에 묶여 테스트·교체가 어려워진다. |
| Controller → 인프라 직접 의존(INTERFACES_IMPORTS_INFRA) | 진입점이 중간 계층 없이 DB·외부 연동 코드를 직접 import한다. |
| DB 계층 건너뛰기(DB_LAYER_BYPASS) | Repository(저장소 계층)를 거치지 않고 DB에 직접 접근한다 — 검증·트랜잭션 규칙이 우회될 수 있다. |
| 다른 도메인 내부 참조(CROSS_CONTEXT_IMPORT) | 한 도메인 모듈이 다른 도메인의 내부 클래스를 직접 import한다 — 모듈이 얽혀 분리·수정이 어려워진다. |
| 도메인 경계 넘는 호출(CROSS_DOMAIN_CALL) | 다른 도메인의 함수를 중간 인터페이스 없이 직접 호출한다. |
| 기능 폴더 간 직접 참조(CROSS_FEATURE_IMPORT) | 기능 폴더(features/A)가 다른 기능 폴더(features/B)를 직접 import한다(Feature-Sliced Design류 프로젝트에서 자동 감지). |
| 레이어 단방향 위반(FEATURE_LAYER_VIOLATION) | app → features → shared 한 방향이어야 하는 의존이 거꾸로 됐다. |
| 레이어 역전 의존(LAYERED_REVERSE_DEPENDENCY) | 아래 계층(Repository 등)이 위 계층(Controller 등)을 import한다(레이어드 아키텍처 프로젝트에서 자동 감지). |
| Service 계층 건너뛰기(LAYERED_BYPASS) | Controller가 Service를 건너뛰고 Repository를 직접 호출한다. |
| 선언한 구조 규칙 위반(INTENT_DRIFT) | 사용자가 직접 선언한 모듈 경계·금지 의존 규칙("아키텍처 의도")을 어긴 경우(선택 기능, opt-in). |
| 공유 데이터베이스 안티패턴(SHARED_DATABASE_ACCESS) | 모노레포의 서로 다른 서비스가 같은 DB 테이블을 함께 접근한다. |
| 서비스 간 동기 호출 체인(SERVICE_CALL_CHAIN) | 서비스 간 동기 호출이 2홉 이상 연쇄된다 — 분산 모놀리스 신호. |
| 순환 빈 의존(CIRCULAR_BEAN_DEPENDENCY) | Spring 빈끼리 생성자 필드로 서로를 순환 참조한다 — 앱 기동 실패로 이어질 수 있다. |
| @Async 자기 호출(ASYNC_SELF_CALL) | 같은 클래스 안에서 @Async 메서드를 부르면 비동기가 조용히 무시된다(Spring 프록시 한계). |
| @Transactional 누락(MISSING_TRANSACTIONAL_DELETE) | Spring Data 파생 삭제 쿼리에 트랜잭션 경계가 없다 — 런타임 예외로 이어질 수 있다. |
| @Convert 마이그레이션 필요(MISSING_CONVERTER_MIGRATION) | 암호화 등 컬럼 변환기를 붙였는데 기존 데이터를 변환하는 마이그레이션이 안 보인다. |
| 인터페이스 미구현(BROKEN_INTERFACE_CHAIN) | 인터페이스 선언만 있고 연결된 구현을 찾지 못했다 — 미완성 코드거나 죽은 선언일 수 있다. |
| 데드 코드 후보(DEAD_CODE) | 프로젝트 안에서 호출하는 곳을 찾지 못한 함수. |
| 한 함수에 몰린 책임(HIGH_FAN_OUT) | 함수 하나가 7개 넘는 함수를 호출한다 — 역할 분리를 검토할 신호(참고용, 강제 아님). |

**게이트 등급.** 경고는 전부 무료로 보이지만, "PR을 실제로 막을지"는 3단계로 나뉜다 — 0단계(런타임에 실제로 깨지는 버그류, 항상 막음)·1단계(구조 규칙, 프로젝트별로 켜고 끔)·2단계(실험적, 옵트인). 대부분의 경고는 프로젝트 설정에서 오탐이면 패턴 예외로 끄거나, 개별 건은 숨길 수 있다.

## 6. 사람들과 함께 쓰는 부분

- **공유**: 그래프를 로그인 없이 볼 수 있는 링크로 공유(소유자 화면과 거의 동등하게, 저장/수정만 제외).
- **커뮤니티**: 마크다운 글 작성 + 그래프 스냅샷 첨부, 팔로우, 좋아요/북마크/댓글, 갤러리(그래프 첨부 글만 모아보기).
- **실시간 협업**: 같은 그래프를 여러 명이 동시에 보며 커서 공유 + 팀 채팅.
- **팀**: 좌석제로 팀을 만들어 프로젝트를 배분하고 함께 관리(멤버는 소유자와 거의 동일 권한).
- **AI 코딩 에이전트 연동**: 그래프를 마크다운으로 내보내 Claude Code 같은 AI 에이전트에 컨텍스트로 붙여넣을 수 있다. 본인 LLM API 키(BYOK — Anthropic/OpenAI/Gemini 중 등록)를 연결하면 주석 없는 함수의 역할을 추정 요약하고, 컨텍스트(도메인) 단위로 기능명세도 생성해준다 — 코드는 서버에 저장되지 않고 그 요청에서만 사용되며, 여러 키를 등록하면 하나가 실패(인증/사용량 초과)할 때 다음 키로 자동 전환된다.
- **DDD 마이그레이션 후보 가이드**: 도메인/기능 구조가 감지되지 않는 프로젝트에서는, API 엔드포인트별 실행 경로를 추적해 자주 함께 쓰이는 파일을 후보 모듈로 묶어 제안한다. LLM 없이 계산되는 무료 기능(BYOK 불필요)이며, 이미 구조가 있는 프로젝트에서는 아무것도 추가되지 않는다.
- **AI 내보내기 차단(DLP)**: 코드가 외부 LLM으로 전송될 가능성을 원천 차단하고 싶은 프로젝트는 이 토글을 켜면 된다 — UI에서 숨기는 게 아니라 서버가 요청 자체를 강제로 거부한다.
- **웹 없이 로컬에서**: `codeprint-explore`·`codeprint-analyze` 두 Claude Code Skill을 무료 공개해뒀다 — 로그인·프로젝트 생성 없이 로컬 저장소에서 바로 쓸 수 있다.

## 7. 무료로 되는 것 / 유료인 것

**판정(경고)과 시각화는 전부 무료다** — 이게 이 서비스의 핵심 가치이기 때문에 유료 벽 뒤에 두지 않는다. 유료 경계는 "자동화"와 "협업 규모" 축에 있다:

- 비공개 프로젝트는 계정당 6개까지(공개 프로젝트는 무제한) — 무료 티어의 저장 비용 관리 목적.
- 팀 협업은 좌석제 결제(팀 생성·정식 팀원 관리).
- (계획 단계) 로컬 자동 감지(파일 저장 시 즉시 재검사) 같은 상시 자동화는 데스크탑 유료 축으로 구상 중 — 지금은 개발 중이며 상세 조건은 확정되지 않았다.

## 8. 기술적으로는 어떻게 동작하는가 (요약)

GitHub URL을 받으면 shallow clone 후, 언어별 tree-sitter AST 파서(정규식은 안전망)로 함수·import·DB 접근·API 엔드포인트 등을 추출해 그래프로 조립하고, 순수 함수 형태의 감지기가 그 그래프만으로 20종 경고를 계산한다. Java/Python/TypeScript·JavaScript/Go/Rust/C#/Ruby/PHP/C/C++/Swift/Kotlin 13개 언어를 지원한다. 백엔드는 Java/Spring Boot(DDD), 프론트는 React/TypeScript다. 더 자세한 내용은 [`ARCHITECTURE.md`](ARCHITECTURE.md)·[`ANALYSIS_ENGINE.md`](ANALYSIS_ENGINE.md)·[`PROJECT.md`](PROJECT.md) 참조.
